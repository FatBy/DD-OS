# DunCrew 新手使用指南

> 读这份指南大概需要 15 分钟。读完你就能用 DunCrew 做出你的第一篇研究报告、第一本小说草稿，或者第一个小程序。

---

## 一、DunCrew 是什么？

你可以把 DunCrew 想象成一间开在你电脑里的 **"AI 事务所"**。

过去你用 ChatGPT、DeepSeek 这些 AI 聊天工具，就像在路边问一个陌生人问题——他每次都不认识你，每次都要从头解释。而 DunCrew 不一样，它给你配了一整个**会成长的 AI 员工团队**：

- 你可以**派任务**给它们（比如"帮我写一本科幻小说"）
- 它们会**自己动手**（打开文件、上网搜资料、写文档、跑代码）
- 它们会**记住你**（你合作过的事、你的喜好、上次写到第几章）
- 它们会**越用越聪明**（失败一次会反思，下次就不犯同样的错）

一句话总结：**它不是一个聊天框，是一间能给 AI 上班的写字楼。**

## 二、几个你必须先认识的"小伙伴"

DunCrew 里有一些专有名词，我用大白话给你对应上：

| 名词 | 你就当它是 | 用来做什么 |
|------|-----------|-----------|
| **Dun（墩）** | 一位专业员工 | 每个 Dun 只擅长一件事，比如写小说、做 PPT、查资料。你派活给对应的 Dun 效果最好 |
| **Skill（技能）** | 员工的"本领" | 比如"上网搜索"、"读写文件"、"做 PPT"是一个个技能，员工可以装备多个技能 |
| **Memory（记忆）** | 员工的笔记本 | 每次干活的过程、结论都会被记下来，下次接着用 |
| **Wiki（知识库）** | 员工的小百科 | 做一件事时积累的"常识"，以后再做类似事情直接调用 |
| **Nexus** | 一个工作岗位 | 把 Dun + 技能 + 工作流程打包成固定岗位，比如"小说大师"岗 |

内置就有 6 位现成员工：

- **novel-master**：写小说的
- **paper-killer**：写论文的
- **competitive-analyst**：做竞品调研的
- **xiaohongshu-writer**：写小红书文案的
- **private-lawyer**：看合同、过法律文件的
- **zhouyi-diviner**：算卦解卦的（没错，这也能算）

## 三、第一次安装（照着做就行）

### 你的电脑需要满足：

| 需要什么 | 版本 | 怎么检查 |
|---------|------|---------|
| Node.js | 18 以上（推荐 20+） | 打开命令行输入 `node -v` |
| Python | 3.10 以上 | 命令行输入 `python --version` |
| Git | 任意新版本 | 命令行输入 `git --version` |

如果这三个命令有任何一个报错"不是内部命令"，说明你没装。去官网下载安装一下就好：

- Node.js：`https://nodejs.org`
- Python：`https://python.org`（安装时一定要勾 **Add Python to PATH**）
- Git：`https://git-scm.com`

### Windows 用户最省事的方式

项目里已经帮你写好了一键启动脚本，你只需要：

1. **下载代码**：打开命令行（cmd 或 PowerShell），进入你想放项目的文件夹，执行：
   ```
   git clone https://github.com/FatBy/DunCrew.git
   cd DunCrew
   ```

2. **安装依赖**（只需要做一次，耐心等几分钟）：
   ```
   npm install
   pip install -r requirements.txt
   ```

3. **启动**：在项目文件夹里双击 `DunCrew.bat`（开发模式，自动拉起前后端），或者双击 `start-standalone.bat`（独立运行模式，使用预编译的服务端）。

搞定，等它自己把后端和前端都拉起来。启动完成后浏览器会自动打开 `http://localhost:3001`。

### Mac / Linux 用户

开两个终端窗口：

```
# 第 1 个窗口：启动后端
python duncrew-server.py --port 3001

# 第 2 个窗口：启动前端
npm run dev
```

然后浏览器打开 `http://localhost:5173`（开发模式）或 `http://localhost:3001`（生产模式）。

## 四、配置 AI 大脑（关键一步）

DunCrew 自己不会思考，它需要借一个 AI 模型的"脑子"来用。这一步不做，任何功能都用不了。

1. 打开 DunCrew，看**左侧边栏**，找到 **Settings（设置）**，点进去。
2. 你要填三样东西：
   - **Base URL**：AI 服务的地址
   - **API Key**：你的密钥（花钱买的或者免费领的那串字符）
   - **Model**：模型名字

3. 去哪儿领 API Key？下面几家任选其一：

| 服务商 | 推荐模型 | Base URL | 备注 |
|--------|---------|----------|------|
| DeepSeek | `deepseek-chat` | `https://api.deepseek.com/v1` | **便宜，新手首选** |
| 通义千问 | `qwen-plus` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 国内访问稳定 |
| OpenAI | `gpt-4o` | `https://api.openai.com/v1` | 效果最好，但贵、需科学上网 |
| 硅基流动 | 多种开源模型 | `https://api.siliconflow.cn/v1` | 新用户送额度 |

> **新手提示**：先用 DeepSeek。注册账号 → 控制台创建 API Key → 复制粘贴进 DunCrew → 保存。成本大概是 1 块钱能聊一整天。

填完点保存，你会看到一个小小的"连接成功"提示，这一步就通了。

## 五、用起来：你的第一个任务

DunCrew 的主界面长得像一张**世界地图**，每个小岛/小屋就是一个 Dun（员工）。你不是在一个聊天框里打字，而是**先走进一个员工的办公室，再跟他说话**。

### 上手练习 1：让它帮你写一份调研报告

1. 在世界视图里**点一下任意一个 Dun**（新手直接选 `competitive-analyst`，中文意思是"竞品分析师"）。
2. 右侧会滑出这个 Dun 的专属聊天面板。
3. 在输入框里贴这段话：

   ```
   帮我调研一下 2025 年 WebAssembly 的发展现状，
   包括：浏览器支持情况、服务端应用、哪些大公司在用。
   最后写成一篇结构化报告，保存成 wasm-report.md。
   ```

4. 按回车，然后就**看着它干活**。

### 它干活时你会看到什么？

右侧面板会一步步显示它的思考过程，大概像这样：

```
第 1 步 / 共 5 步：搜索浏览器支持情况
  正在调用工具：webSearch("WebAssembly 浏览器支持 2025")
  ✅ 已找到相关资料

第 2 步 / 共 5 步：搜索服务端应用
  正在调用工具：webFetch("https://...")
  ✅ 已读取页面

... （中间步骤省略）

第 5 步 / 共 5 步：写入报告文件
  正在调用工具：writeFile("wasm-report.md")
  Critic 验证：✅ 文件已生成，结构完整

任务完成 🎉
```

任务跑完后，在项目的数据目录（`DunCrew-Data/documents/`）下会真的多出一个 `wasm-report.md` 文件。**这不是虚构的文字，是真的保存在你硬盘上的文件。**

### 上手练习 2：写一本小说的开头

1. 进入 `novel-master`（小说大师）。
2. 贴这段话：

   ```
   我想写一本硬科幻小说，叫《最后的信号》。
   背景：2187 年，人类已经殖民火星，但和地球失联了 3 年。
   主角是火星空间站的无线电工程师，某天捕捉到了来自地球的微弱信号。
   请从你的 SOP 第一阶段（项目启动）开始做。
   ```

3. 它会自动建一个项目文件夹，里面有：
   - `worldbuilding.md`（世界观设定）
   - `characters.md`（人物设定）
   - `outline.md`（全书大纲）
   - `chapters/chapter-01.md`（第一章）

4. 过几天你再打开 DunCrew，只要说 **"接着上次第 3 章继续写"**，它真的记得之前所有情节。

### 上手练习 3：让它写点代码

1. 进入任意一个偏编程的 Nexus（比如 `skill-scout`）。
2. 贴这段话：

   ```
   帮我用 TypeScript 写一个工具库叫 datekit，包含：
   1. formatRelative(date)：输出"3 小时前""2 天后"这样的格式
   2. parseNatural(str)：能把"下周五""上个月"解析成 Date 对象
   3. rangeOverlap：判断两个日期区间是否重叠
   另外配上 Vitest 单元测试，初始化成一个标准 npm 包。
   ```

3. 它会：建目录 → 装依赖 → 写三个函数 → 写测试 → 跑测试。
4. 如果测试失败了，**它不会傻乎乎地重试**，而是触发所谓的 **Reflexion（反思）**，分析为什么错，然后只改错的那一段，再测一遍。

## 六、八大功能模块速查

DunCrew 左侧栏有 8 个"房间"，每个管一摊事：

| 房间名 | 大白话解释 | 什么时候用 |
|--------|-----------|-----------|
| **世界**（World） | 员工地图 | 选一个 Dun 开始干活，2.5D 等距视角的虚拟工作空间 |
| **任务监控**（Task） | 正在跑什么活 | 看进度、看 AI 当前在想什么、查看执行日记 |
| **技能树**（Skill） | 技能仓库 | 看有哪些技能、给员工装备技能、自己创建新技能。分"神经元"和"技工学院"两个子视图 |
| **记忆宫殿**（Memory） | 员工的记忆库 | 查 AI 之前记住了什么、查看碱基分析面板、管理技能记忆 |
| **灵魂塔**（Soul） | 员工的性格设定 | 调整 AI 的说话风格、MBTI 人格、审批行为修正案 |
| **联络站**（Link Station） | 模型通道和外挂接口 | 配置 AI 模型通道、接入 MCP 服务器 |
| **知识库**（Library） | 你的资料库 | 包含"图书馆"和"自习室"两个子模块（下面详细说） |
| **设置**（Settings） | 系统配置 | 视觉效果、世界主题、语言切换、ClawHub 账户管理 |

### 知识库的两个子模块

**图书馆**：DunCrew 的知识管理中心。你可以把各种知识实体（概念、术语、经验）存进去，AI 在干活时会自动检索参考。支持语义搜索、分类浏览、批量导入导出、知识健康度评估（自动发现空壳实体和冲突内容）。还内置了一个 LLM Librarian，像个图书管理员一样帮你整理知识。

**自习室**：AI 辅助写作工作台。和直接在聊天框里让 AI 写东西不同，自习室提供了**专业的写作环境**——左边是文章编辑区，右边是 AI 对话框，你可以一边写一边和 AI 讨论修改。支持版本历史管理、版本对比回滚、文风指纹识别（保持全文风格一致）。适合写长文、论文、报告等需要反复打磨的内容。

**小白只需要先玩转"世界 + 任务监控"就够了**，其他的以后慢慢探索。

## 七、关于安全（很重要）

DunCrew 能真的在你电脑上**执行命令、创建/修改文件**。为了不误操作，它内置了三道安全门：

### 1. 危险操作自动拦截

像 `删除整个硬盘`、`格式化 C 盘` 这种命令，AI 想跑也跑不了，会被直接拦截。

### 2. 高风险操作要你批准

碰到这类命令（比如安装全局软件、改系统配置），AI 会**弹出一个对话框**问你：

> "我想执行命令 `xxx`，你同意吗？[同意] [拒绝]"

你不点"同意"它就不会动。**看不懂的命令请一律先点拒绝**，没事的。

### 3. API Key 和数据完全留在你电脑上

- API Key 只存在你的浏览器 localStorage 里，**不会上传**
- 后端服务只监听 `127.0.0.1`（你本机），**外网访问不到**
- 所有 AI 生成的文件都在你的 `DunCrew-Data/` 文件夹，**你随时可以翻、可以删**

## 八、常见问题自救

### Q1：点了 Dun 没反应 / 聊天发不出去

大概率是后端没起来。打开命令行输入：

```
netstat -ano | findstr 3001
```

如果**什么都没返回**，说明后端挂了。手动启动一下：

```
python duncrew-server.py --port 3001
```

### Q2：AI 回复说"API Key 无效"

1. 去 Settings 里确认 Key 复制完整（前后不要有空格）
2. 确认 Base URL 写对了（每家服务商不一样）
3. 确认你账户里还有余额

### Q3：任务跑到一半卡住了

点界面上的**停止按钮**，然后重新派一遍任务。AI 的记忆还在，它会记得上次做到哪儿。

### Q4：AI 写的内容我不满意怎么办？

直接在对话框里告诉它，就像和真人同事说话一样：

- "这段太啰嗦了，精简到 100 字以内"
- "第二章的反派动机不够合理，重新设计一下"
- "这份报告再加一节关于性能对比的内容"

**它记得之前的所有内容**，不用你重新解释背景。

### Q5：我想让 AI 学会一个新本领，能教吗？

可以。在 `skills/` 目录下新建一个文件夹，写一个 `SKILL.md` 文件描述这个本领。技能是**热加载**的，不用重启就能被识别。

最简单的模板：

```markdown
---
name: 我的技能名
description: 这个技能能干嘛
version: 1.0.0
---

# Instructions

这个技能具体怎么运作……
```

## 九、碱基系统（Base Sequence）——让 AI 的行为"可被观测、可被治理"

这是 DunCrew 最硬核、也最独特的一个设计。它借用了生物学里 **DNA 由四种碱基组成** 的比喻，把 AI 每一步操作也抽象成四种"碱基"，串起来形成一条"行为 DNA"，然后用纯代码（**不调用任何 LLM**）实时监控这条序列、在必要时干预 AI。

### 1. 先认识四种碱基：E / P / V / X

AI 每调用一个工具（写文件、跑命令、搜网页……），都会被自动打上一个标签：

| 碱基 | 英文 | 含义 | 典型例子 |
|------|------|------|---------|
| **E** | Execute | **执行**：AI 很清楚要干嘛、信息也够，直接动手 | 写代码、写报告、保存文件 |
| **P** | Plan | **规划**：AI 在制定计划、拆解子目标 | 输出"分三步走：先 A、再 B、最后 C" |
| **V** | Verify | **验证**：AI 在检查上一步的结果对不对 | 写完文件后读回来、跑完代码后跑测试 |
| **X** | eXplore | **探索**：AI 不知道情况，正在摸底 | 搜网页、列目录、读从没访问过的文件 |

所以 AI 做一个任务的过程，就会产生一串像这样的字符串：

```
X-X-P-E-E-V-E-V
（先摸底 → 摸底 → 规划 → 执行 → 执行 → 验证 → 执行 → 验证）
```

**这就是一条"碱基序列"，也就是这个 AI 这次任务的 DNA。**

### 2. 光有序列没用，关键是看它健不健康

研究发现，**好任务的序列和烂任务的序列长得不一样**。比如：

- **健康**：`P->E->V` 交替出现（规划后执行，执行后验证），这是"黄金路径"，历史成功率 96.9%
- **不健康①**：序列末尾一串连续 `X`（比如 `...X-X-X-X-X`），说明 AI 在"鬼打墙"，一直在探索却出不来
- **不健康②**：相邻碱基频繁切换（`X-E-X-E-X-E`），说明策略飘忽，没深入
- **不健康③**：任务已经过半，却还在冒出新的 `P`（重新规划），统计显示这类路径成功率只有 77%
- **不健康④**：最近 5 步全是同一种碱基，说明**多样性崩溃**，陷入了死循环

DunCrew 会从序列里**实时提取 8 维核心特征**（末尾连续 X、总步数、最近 5 步 X 占比、切换率、后半段 P 出现率、最长连续 E、X/E 比等），用这些指标来评估"这只 AI 现在状态正不正常"。

### 3. 治理器（Governor）：发现异常就悄悄"提醒" AI

这是碱基系统的核心——一个叫 **Base Sequence Governor** 的治理器，每执行一步就检查一次序列。它像一个空调恒温器：**传感器（碱基分类器） + 规则（if/else） + 执行器（在 prompt 里注入一句话提醒）**。

目前内置 7 条规则（默认只启用部分，你可以在 UI 里自由开关）：

| 规则名 | 触发条件 | 会往 AI 耳朵里"塞"什么话 |
|--------|---------|----------------------|
| **连续探索刹车** | 末尾连续 X >= 阈值 | "已连续 N 次探索未获进展，请换一个完全不同的策略" |
| **序列长度熔断** | 总步数 >= 阈值 | "任务已执行 N 步，请尽快收敛到最终结果" |
| **策略一致性提示** | 切换率 > 60% | "你在不同方向间频繁跳跃，请集中精力在一个方向深入" |
| **多样性崩溃** | 最近 N 步全同 | "陷入了重复循环，请尝试不同的操作类型" |
| **后期规划警告** | 过半了还在 P | "后期规划成功率显著低于早期规划，直接用已有信息执行" |
| **验证缺失提醒** | 最近 N 步没有 V | "建议在执行操作后添加验证确认结果正确" |
| **探索过度** | X/(X+E) > 55% 且步数 >= 6 | "你探索得太多、执行得太少，该动手了" |

除了这 7 条硬编码规则，系统还支持**数据发现规则**——通过 Python 后端的统计分析管线自动挖掘新规则，走 `candidate -> validated -> retired` 的生命周期，只有经过统计验证的规则才会上线。

**这些提醒不是打断 AI，而是悄悄拼进下一轮的 prompt 里**，让 AI 自己读到、自己调整。整个过程 0 延迟、不花 token，因为完全是纯代码规则。

### 4. 治理器的三层架构（了解即可）

这部分小白不用深究，留个印象就行：

```
Layer 1：在线规则引擎
  每一步都评估，触发规则 -> 立刻注入 prompt
  支持硬编码规则 + 数据发现规则双路径
  （相当于"实时交警"）

Layer 2：统计累加器
  每个任务跑完后，按 4 维 x 72 个桶分桶统计成功率
  干预组 vs 未干预组的对比数据都留着
  还能做反事实预测——"如果不干预会怎样"
  （相当于"交通摄像头在默默记录"）

Layer 3：阈值自适应
  攒够 50 条数据后，用卡方检验（Yates 校正）算一次：
    "连续 X 刹车"的阈值设 12 合理吗？还是设 10 更好？
  只有统计显著才调整，否则保持现状（安全阀）
  （相当于"交通部门根据数据调整限速值"）
```

**最妙的是 Layer 3**：规则的阈值不是拍脑袋定的，是系统自己用你的数据慢慢调出来的。你用得越久，这套规则越贴合你的使用场景。

### 5. 转录酶（Transcriptase）：序列还能控制"分裂子 Agent"

生物学里，转录酶是读 DNA、输出 mRNA 的酶。DunCrew 里的 **Transcriptase Engine** 做同样的事——**读取碱基序列，决定要不要 spawn 一个子 Agent 去分担工作，或者直接终止失控的任务**：

- **子目标分裂**：步数 >= 8 且发现了多个子目标 -> 分裂一个子 Agent 专门处理其中一个
- **失败路径委托**：末尾连续 3 个 X 且已有失败记录 -> 派个子 Agent 试试替代方案
- **探索聚焦**：探索/执行比 > 60% 且发现了 5+ 个资源 -> 分裂一个专注执行的子链
- **规划过度熔断**：P 占比 > 25% 且步数 >= 15 且已有失败 -> 直接终止任务（置信度 0.85）
- **探索死亡螺旋**：连续 X >= 5 且步数 >= 15 且已有失败 -> 直接终止任务（置信度 0.90）

后两条是"abort"类型的决策——不是派分身，而是直接拉闸。当 AI 已经在泥潭里挣扎太久，继续耗下去只会浪费 token，不如果断终止。

这就是为什么 DunCrew 处理复杂任务时，有时你会看到它"派出分身"同时干活——不是随便派的，是序列算出来该派才派的。

### 6. 碱基系统和 Gene Pool 的区别（容易混淆，重点说一下）

这两个都用了生物学比喻，但完全是两码事：

| 对比项 | 碱基系统（Base Sequence） | Gene Pool（基因池） |
|--------|-------------------------|-------------------|
| **管什么** | 当前这一次任务的**行为序列** | 历史任务积累的**修复经验** |
| **粒度** | 每一步工具调用都打标 | 每条成功修复打包成一条"基因" |
| **时机** | 任务进行**中**实时监控 | 任务结束**后**收割，下次任务**开始**时匹配 |
| **用 LLM 吗** | **完全不用**，纯代码规则 | Reflexion 阶段会让 LLM 参考 |
| **类比** | DNA 序列 + 转录酶 | 遗传特征 + 基因表达 |

一句话区分：**碱基系统治的是"现在"，基因池传承的是"过去"。**

### 7. 在哪儿能看到碱基序列？

- **记忆宫殿 -> 碱基分析面板（Base Analysis Panel）**：能看到每次任务的完整序列、8 维特征、N-gram 模式分析、Token 效率分析、触发了哪些规则、候选规则状态、干预效果如何
- **任务监控**：任务跑的时候，右侧面板会实时显示当前序列（形如 `X-X-P-E-E-V...`）和每一步的碱基类型
- UI 里也可以**开关某条规则**——比如你觉得"连续探索刹车"太激进，可以单独关掉它

### 8. 一个直观的例子

你让 `competitive-analyst` 调研一个冷门话题。它可能走出这样的序列：

```
X  -> 搜索关键词（没搜到什么）
X  -> 换个关键词再搜（还是不行）
X  -> 列目录看看本地有没有相关文档
X  -> webFetch 某个可疑链接
X  -> 还是没获得有用信息
```

此时序列变成 `X-X-X-X-X`。**治理器的"连续探索刹车"规则触发**，悄悄往下一轮 prompt 里塞了一句话："已连续 5 次探索未获实质进展，请换一个完全不同的策略。"

AI 读到这句话，下一步不再执着于继续搜，而是切换成 `P`（重新规划，比如"这个话题可能需要从 X 角度切入"），然后是 `E`（用新角度直接产出），序列变成：

```
X-X-X-X-X-P-E-V
```

**于是任务从"鬼打墙"被救回来了，而整个过程你不需要做任何干预**——这就是碱基系统的价值。

## 十、其他用得越久越爽的成长机制

除了碱基系统，DunCrew 还有几个"会成长"的机制，放在一起对比着看更清楚：

- **双层记忆（L0 / L1）**：每个 Dun 有自己的私人记忆（L1），初始置信度 0.35，通过 Critic 验证（+0.15）、用户正面反馈（+0.10）等信号逐步积累。当置信度 >= 0.50 且积累了至少 2 个信号后，自动"晋升"到全局核心记忆（L0），所有 Dun 共享。不活跃的记忆会按 30 天半衰期自然衰减。相当于"个人笔记本 -> 公司知识库"的自动晋升流水线。
- **Gene Pool（基因池）**：每次任务结束后，系统会自动扫描"失败->反思->成功"的三连模式，把这段经验打包成一条"基因"（置信度 0~1、会随使用增减、会自然衰减）。下次任何 Dun 遇到相似错误，系统自动把对应基因注入 Reflexion 上下文，让 AI "继承"历史修复经验。**基因是跨 Dun 共享的**，novel-master 踩过的坑能让 competitive-analyst 免疫。基因选择使用 Thompson Sampling 策略，确保好基因被优先使用。
- **SOP 进化**：每个 Nexus 都有自己的标准作业流程（SOP），系统跟踪每一步的成功率（EMA 指数移动平均）。触发条件分三级：最近 3 次全失败（紧急改写）、执行 >= 5 次且 EMA < 0.50（标准改写）、执行 >= 10 次且 EMA < 0.70 且近期下滑（渐进改写）。还会从成功案例中提炼"黄金路径"——**流程自己会优化自己**。
- **观察者（Observer）**：后台默默分析你的使用习惯，通过"Skill 发现"和"Dun 发现"双路径分析。发现你常做"搜索 -> 读网页 -> 摘要 -> 写 markdown"这套组合，会主动建议："要不要把它打包成一个新技能？"被拒绝的建议会进入冷却期，不会反复打扰你。
- **评分系统**：每个 Dun 有 0-100 熟练度评分，连续成功有 streak 加成，用得越多评分越高。
- **灵魂进化**：Dun 的 MBTI 人格不是死的，会根据长期互动慢慢微调，生成"行为修正案"供你审批。

### 整体来看，DunCrew 的"成长"是多层级叠加的

| 层级 | 机制 | 作用时机 |
|------|------|---------|
| **单步级** | 碱基分类 + Critic 验证 | 每一步工具调用 |
| **序列级** | Base Sequence Governor | 每轮 ReAct 循环末尾 |
| **任务级** | Reflexion + Transcriptase | 失败时 / 达到阈值时 |
| **任务后** | Gene Pool 收割 + 观察者分析 | 任务结束 |
| **长期级** | SOP 进化 + L1->L0 晋升 + 灵魂修正 | 累积足够样本后 |

**所以 DunCrew 用得越久越难被替代**。你换个新模型进来，它套上你现有的基因池、记忆、SOP 和治理器阈值，立刻就能拥有"和你磨合了三个月的员工"的水平。

## 十一、最后一点建议

1. **别一开始就问太复杂的任务**。先从"帮我搜一下 xxx 写成报告"这种单一任务练手，感受它的节奏。
2. **任务描述越具体越好**。不要说"写点东西"，要说"写一篇 800 字、面向中学生、关于气候变化的科普文章，保存成 md 文件"。
3. **不要怕它出错**。AI 失败了会反思会重试，你只要观察、提要求就行。
4. **多用同一个 Dun**。同一个员工越用越懂你，换来换去它就记不住你的偏好。
5. **遇到不懂的按钮，先把鼠标悬停**，大部分都有 tooltip 提示。
6. **善用自习室写长文**。如果你要写论文、报告这类需要反复打磨的内容，去知识库的"自习室"比直接在聊天框里写效果好得多。
